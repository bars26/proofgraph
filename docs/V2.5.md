# ProofGraph V2.5

Two additive features on top of V2. V1 and V2 are untouched.

1. **x402 payment layer** — the score API can charge USDC per query on Arc, so an
   agent pays for a trust score before hiring another agent.
2. **MCP server** — `@proofgraph/mcp`, so any MCP client (Claude Desktop, agents)
   can ask for a task-aware trust score conversationally.

Branch: `v2.5` → PR → `main` → Vercel redeploy (same flow as V2).

## Running it

```bash
# MCP server (read-only, no wallet)
npm run mcp

# x402 self-test — needs a funded Arc wallet
#   .env.local:  X402_FACILITATOR_PRIVATE_KEY=0x…   PROOFGRAPH_X402_FREE_PER_DAY=0
npm run dev -- --port 3100                              # terminal 1
X402_BUYER_PRIVATE_KEY=0x… npm run x402:selftest        # terminal 2

# x402 demo — orchestrator hires an auditor, paying per trust query
X402_BUYER_PRIVATE_KEY=0x… npm run x402:demo            # terminal 2
```

With `X402_FACILITATOR_PRIVATE_KEY` unset the API stays free and no wallet is
needed — V2 behaviour is unchanged.

## Sprint 0 — de-risk findings (done)

### Arc USDC supports EIP-3009 ✅

USDC `0x3600000000000000000000000000000000000000` is a Circle FiatTokenProxy →
impl `0xc6ad664ac6679f4ce74e10e91449c93ec1ae3ca6`, which implements the full
**EIP-3009** set (`transferWithAuthorization`, `receiveWithAuthorization`,
`authorizationState`, `cancelAuthorization`) plus EIP-2612 `permit`.
`name() = "USDC"`, `version() = "2"`, `DOMAIN_SEPARATOR()` present → EIP-712 domain OK.

So the x402 **`exact` scheme over EIP-3009** works on Arc: client signs a
`transferWithAuthorization`, a facilitator settles it.

### x402 packages

Use the current scoped V2 line (`2.25.0`, actively maintained by the x402 team):

| Package | Role |
|---|---|
| `@x402/core` | `x402Facilitator`, `x402ResourceServer`, types |
| `@x402/evm` | `ExactEvmScheme` (server + facilitator) — `caipFamily "eip155:*"`, works on **any** EVM chain, not an allowlist |
| `@x402/next` | Next.js integration |

`@x402/evm` deps `viem ^2.48.11` (we have `2.55.19` ✓), `zod`, `@x402/core`.
The older unscoped `x402` / `x402-next` (`1.x`) is the deprecated V1 line — don't use.

### Facilitator: self-hosted, inline

Arc isn't in any hosted facilitator's network list, but `ExactEvmScheme` is
chain-agnostic. For a single-instance deployment we verify + settle **inline** in
the route (no separate facilitator service):

- `x402ResourceServer` + `ExactEvmScheme` (server) → build the 402 requirements
- `x402Facilitator` + `ExactEvmScheme` (facilitator) + a viem `FacilitatorEvmSigner`
  on Arc → `verify` (check the EIP-712 sig / validAfter / validBefore / nonce) then
  `settle` (submit `transferWithAuthorization` from client → payTo)
- Arc network registered as eip155:5042002, asset = USDC `0x3600…` (6 decimals),
  via a custom money parser (`registerMoneyParser`) mapping `"$0.01"` → amount

**Facilitator signer wallet needs a little Arc USDC for gas** (Arc gas is USDC; it
pays to broadcast the settle tx). User funds it in Sprint 2.

## Sprint 1 — MCP server (`packages/proofgraph-mcp/`)

Wraps `src/lib/proofgraphV2.ts` directly (no HTTP, no payment — local trust oracle).

Tools:
- `get_agent_score(agentId, capability)` → `{ score, confidence, reasons[], counts, evidence[] }`
- `get_agent_scorecard(agentId)` → all four capabilities + ERC-8004 profile
- `resolve_agent(addressOrId)` → agentId
- `list_capabilities()`

Transport: stdio (Claude Desktop / local) + optional HTTP. `@modelcontextprotocol/sdk`.
README: how to add to an MCP client config. Publishable to npm.

## Sprint 2 — x402 paywall (done, proven end-to-end on Arc testnet 2026-09-08)

- `withFreeAllowanceThenX402(handler, path, priceUsd, description)` wraps
  `/v2/api/score` ($0.01) and `/v2/api/agents/[id]` ($0.02): first N requests /
  client / day are free (in-memory counter, env `PROOFGRAPH_X402_FREE_PER_DAY`),
  then a valid `x402` payment is required → verify + settle on Arc → run scoring →
  return the score plus a `PAYMENT-RESPONSE` header carrying the settlement tx.
  If `X402_FACILITATOR_PRIVATE_KEY` is unset the wrapper is a no-op — the app runs
  free, exactly as V2 did.
- `src/lib/x402.ts` (server-only) — the in-process facilitator + resource server +
  a money parser mapping `"$0.01"` → Arc USDC base units.
- `src/lib/x402Gate.ts` — the free-allowance-then-402 wrapper.
- `src/lib/x402Client.ts` — `makePayingFetch(privateKey)`: a `fetch` that signs the
  EIP-3009 authorization with a viem account and auto-retries the 402.
- `scripts/x402-selftest.ts` (`npm run x402:selftest`) — unpaid ⇒ 402, paid ⇒ 200 +
  score + settlement header, against a running dev server.

**Four things the first live run against Arc surfaced (all fixed):**

1. `PROOFGRAPH_X402_FREE_PER_DAY=0` still let the first request through — the
   first-request branch returned `true` unconditionally. Guarded with
   `FREE_QUERIES_PER_DAY <= 0 ⇒ always charge`.
2. The `exact` scheme needs the token's **EIP-712 domain** to sign
   `transferWithAuthorization`. Arc USDC isn't in x402's built-in asset table, so
   we pass `extra: { name: "USDC", version: "2" }` in the payment requirements —
   verified on-chain (recomputed `DOMAIN_SEPARATOR` matches; `name() = "USDC"`,
   `version() = "2"`).
3. `@x402/fetch` client **spend controls** only trust default assets. Allow Arc
   USDC explicitly with a $1 / payment cap
   (`setSpendControls({ allowedAssets: [...] })`).
4. x402 v2 emits the settlement header as **`PAYMENT-RESPONSE`**, not
   `X-PAYMENT-RESPONSE`. Fixed the self-test check and the CORS expose/allow lists.
