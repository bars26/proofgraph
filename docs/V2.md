# ProofGraph V2

**Task-aware reputation for AI agents, backed by verifiable evidence and ERC-8004,
on Arc Testnet.**

Given an agent and a capability, ProofGraph V2 aggregates:

1. structured, hash-committed **evidence** from its own `EvidenceRegistryV2`, and
2. the agent's **ERC-8004** reputation + validation signals

into one **explainable 0–100 score** — and can publish that score back to the
**ERC-8004 Validation Registry** (ProofGraph is a registered validator, `agentId 889819`).

V1 (the `/` route and the original `EvidenceRegistry`) is unchanged and still live.

## Quickstart (query a score in under 5 minutes)

```bash
git clone https://github.com/bars26/proofgraph && cd proofgraph
git checkout v2
npm install
echo "NEXT_PUBLIC_EVIDENCE_REGISTRY_V2=0x99848Ff9527C38c371D5c892a00677b90387aF4a" >> .env.local
echo "PROOFGRAPH_EVIDENCE_BASE_URL=http://localhost:3100" >> .env.local
npm run dev -- --port 3100
```

Then:

```bash
# one capability
curl "http://localhost:3100/v2/api/score?agent=42&capability=Solidity%20Audit"

# full scorecard (all four capabilities + ERC-8004 profile + agent card)
curl "http://localhost:3100/v2/api/agents/42"
```

Or open <http://localhost:3100/v2> and pick a seed agent (`2`, `6`, `42`, `7`).

No server needed for the raw pipeline:

```bash
npx hardhat run scripts/scorecard-v2.ts --network arcTestnet   # live scorecards
npx hardhat run scripts/verify-v2.ts   --network arcTestnet     # hash-verify every record
npx hardhat run scripts/selftest-v2.ts --network arcTestnet     # full assertions
```

## API

### `GET /v2/api/score?agent=<agentId|0xaddress>&capability=<slug>`

`capability` ∈ `Research | Coding | Solidity Audit | Data Analysis`.
`agent` is a numeric ERC-8004 agentId, or a `0x` address (resolved via mint logs;
errors if the wallet owns several agents).

```jsonc
{
  "agent": { "agentId": "42", "address": "0x…", "cardUri": "ipfs://…", "card": { "ok": false, "reason": "…" } },
  "erc8004": {
    "signal": { "repMean01": 0.87, "validationPassRate": 0.5 },
    "reputation": { "total": 30, "active": 30, "revoked": 0, "meanValue01": 0.87,
                    "tags": { "trade_execution": 11, "payment_reliability": 8 } },

  "confidence": "medium",                       // none | low | medium | high
  "penalty": 0,
  "counts": { "evidence": 4, "verifiers": 3, "counterparties": 0, "successes": 4, "failures": 0, "disputed": 0 },
  "successRate": 1,
  "lastEvidenceAt": "2026-08-23T…",
  "reasons": [ "Smoothed success rate 0.75 — …", "3 independent verifier(s) …", … ],
  "terms": [ { "key": "success", "value": 0.75, "weight": 0.45, "applicable": true, "contribution": 0.355 }, … ],
  "evidence": [ { "id": 12, "outcome": "Success", "verifier": "0x…", "counterparty": "0x0…0",
                  "at": "…", "performedAt": "…", "uri": "…", "evidenceHash": "0x…",
```

### `GET /v2/api/agents/<agentId|0xaddress>`

Same, but `capabilities: [ …one entry per capability… ]` instead of a single score.

CORS is `*`; both routes are `force-dynamic`; errors are `{ error, hint }` with
status 400 (bad params) / 422 (unresolvable agent) / 500.

## Submitting evidence

`EvidenceRegistryV2.submitEvidence(agentId, capability, outcome, counterparty, evidenceHash, uri)`

- `agentId` — ERC-8004 IdentityRegistry token id of the subject agent
- `capability` — free string; ProofGraph only scores the four labels above
- `outcome` — `0` Success · `1` Failure · `2` Disputed
- `counterparty` — who the work was for; `address(0)` if undisclosed
- `evidenceHash` — `keccak256(canonicalEvidenceJson(doc))` (see `src/lib/evidenceDoc.ts`)
- `uri` — where that JSON is fetchable

`msg.sender` is recorded as the verifier. The off-chain doc's `performedAt` (ISO) is
what the recency term uses; it may predate the transaction.

The scoring formula (weights, confidence tiers, dispute penalty) is frozen in
[`SPEC.md`](../SPEC.md) §3 as `formulaVersion` `v2.0`.

## What ProofGraph does NOT do (yet)

See [`THREAT-MODEL.md`](../THREAT-MODEL.md) and [`ROADMAP.md`](../ROADMAP.md).
Short version: V2 assumes an honest majority of verifiers; sybil / collusion
resistance, payment limits, and marketplace hooks are V3. **The score is advisory.**
